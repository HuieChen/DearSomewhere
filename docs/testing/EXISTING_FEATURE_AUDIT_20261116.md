# 现有功能细查与修改方案 · 2026-11-16

检查基线：GitHub main `5ba777ee970805455be5e01d5d672c5a3a70895a`。检查范围是已开放的探索试玩版。顺序为源码与状态审查 → 故障复现 → 修改 → 当前引擎/实际导出包回归 → 原生窗口检查。没有把后台测试称为真人试玩。原始美术、已有照片/WAV、旧存档路径及隐藏剧情状态不作重置。

## 先判断当前产品的问题

目前成熟度的主要缺口，是不同工具之间的状态交接还不完整：纸面能正常打开，但在按住键、编辑名称、失去焦点、存储失败、加载中关闭这些边界上，组件各自处理，缺少一致合同。再加上探索内容与未开放故事的界限、旧测试与新行为不同步，会让“单项看着能用”与“连续玩起来可靠”产生差距。本轮优先修复可重复的数据/输入问题，保持已经认可的视觉方向。

## 已复现问题与本轮更改方案

### A01 · P1：录音列表漏掉松键事件，返回现场后可能自行走动

- 路径：打开录音机 → 按住 D → 打开录音列表 → 松开 D → 收起列表。
- 根因：`field_recorder._input` 在列表/名称框拥有焦点时直接返回；`final_walker._tool_movement_keys` 是独立于系统键盘状态的缓存。`walker.cancel()` 取消行走目标，却不清掉工具缓存。
- 影响：松键仍被记为按住；下一次允许移动时，人物继续走。该故障不是走路动画问题。
- 方案：松键在焦点检查之前清除；列表打开、名称/列表获得焦点、窗口失焦、退出工具时统一清除该工具持有的方向键并取消目标。
- 验收：中英两种语言复现同一路径；返回列表后方向为零；正常新按键仍能移动。

### A02 · P1：窗口失焦只停止录音，没有清除显式移动键

- 路径：录音机内按方向键，切换窗口，再回到游戏。
- 根因：`_focus_lost()` 清理的是未实际使用的 `_held` 字典；真正的移动缓存属于 walker。walker 的窗口失焦取消也保留该工具缓存。
- 影响：工具缓存可以绕过普通键盘的窗口焦点条件，产生后台/返回后的意外移动。
- 方案：使用 A01 的统一清理路径；录音仍按现有规则停止并保存，回听停止。
- 验收：失焦后工具键为空，旧录音仍能保存；再次按键可以恢复正常移动。

### A03 · P2：录音列表中的 Esc 没有按层级返回

- 路径：打开录音列表 → 名称框获得焦点 → Esc。
- 根因：局部处理因编辑焦点而跳过；LineEdit/外层对 Esc 的归属不同，没有明确“先退出列表”的规则。
- 影响：编辑状态下返回动作不稳定，也没有把焦点交还给“录音列表”按钮。
- 方案：列表打开时先由录音机接收 Esc，保存名称成功后只收起列表；保存失败则留在原处显示错误。×/收起按钮仍完整关闭录音机。
- 验收：Esc 后录音机仍在，列表隐藏，焦点回到列表按钮；再次 Esc 才退出工具。

### A04 · P2：从背包打开录音时绕过了录音机的正式入口

- 根因：host 直接调用 `library.get_parent().show()`，没有执行内部的暂停、清键、选中焦点和返回处理。
- 影响：同一列表从不同入口打开，键盘体验不同；默认焦点还留在录音按钮。
- 方案：提供明确的 `open_library()`，背包和录音机按钮走同一状态函数。
- 验收：背包 → 录音列表直接聚焦列表、人物停住；关闭工具回背包，原页面保留。

### A05 · P1：照片说明与其他附加信息采用不同恢复规则

- 路径：照片 `.json` 损坏，但 `.json.bak` 是正常记录。
- 根因：`caption_for` 会尝试备份；`photo_metadata` 只读取主文件；`_write_caption` 也只合并主文件，并把 `version` 强行改为 1。
- 影响：同一张照片“说明还在、收藏/地点/原片/胶片参数消失”；再编辑说明可能把残余信息覆盖掉。
- 方案：共用完整 sidecar 读取器，统一从正常主文件或备份读取；编辑仅改变指定字段，保留版本号、未知字段和原片引用。
- 验收：损坏主文件时恢复全部字段；改说明、收藏、重开后地点/参数/未知字段仍一致；原 PNG 不改动。

### A06 · P1：损坏主文件会覆盖最后一份正常备份

- 根因：原照片写入器不判断旧 JSON 是否有效，先删除 `.bak`，再把损坏主文件移入 `.bak`。
- 影响：恢复能力随一次正常编辑消失。
- 方案：统一原子 sidecar 写入：临时文件写入/flush/解析校验 → 有效主文件轮换备份；损坏主文件单独保留原字节，保住有效备份；最终替换失败时尝试恢复旧主文件。
- 验收：故障注入临时路径不可写，返回失败、旧主文件哈希不变；损坏源字节与正常备份均保留。

### A07 · P2：收藏与录音名称采用各自的直接替换逻辑

- 根因：收藏使用 `.favorite.tmp`，录音名称使用 `.json.tmp`，均没有统一的有效备份/恢复策略。
- 影响：同一类用户数据的可靠性不一致。照片刚保存时，附加信息写入也没有等待关闭或检查完整写入错误。
- 方案：照片说明/收藏/拍摄信息与录音名称/地点统一使用本轮 sidecar writer；拍摄信息失败时准确提示“照片已保存；附加信息未保存”。录音 sidecar 失败保留内存待重试，不把 WAV 的成功误当成完整记录成功。
- 验收：真实 PNG/WAV 保留；失败后的重试能补齐名称与地点，不重复生成录音文件。

### A08 · P2：新旅程加载中点关闭，队列之后没有被处理

- 根因：`_close_window_after_save` 在 busy 时设置 `_window_close_deferred`；普通场景切换结束会处理它，`_fresh` 结束却没有处理。
- 影响：玩家点过一次关闭仍停留在游戏，必须再点一次。
- 方案：新旅程加载完成后调用同一延后关闭处理。保持一个点击只触发一次，不跳过存档保障。
- 验收：用 host 子类截获关闭完成事件，加载中请求一次，结束后准确派发一次；测试进程本身不退出。

复现证据：`D:/Codex-build-cache/exploration-audit-20261116/before`。32 个状态断言中 21 个失败，其中包含中英重复和上游数据损坏导致的后续失败，不能解读为 21 个独立 bug。

## 实施顺序与验收边界

1. 先消除录音移动键残留与列表层级问题（A01–A04），走完“现场 → 列表/名称 → 录制/回听 → 背包 → 返回现场”。
2. 合并照片/录音 sidecar 数据保护（A05–A07），用损坏主文件、有效备份、阻塞临时路径验证可恢复性。
3. 修复加载关闭收尾（A08），运行默认检查及当前探索功能回归。
4. 在实际导出包复测，检查中英及 1280/1920/2560 渲染，记录原生窗口实际能完成的操作。

本报告不是全游戏无 bug 证明。完整剧情、跨文件新旅程事务、真人首次游玩清晰度、长时间性能和完整听感仍需独立验证；不关闭工作室 CORE-BOOK/主线制作门槛。
